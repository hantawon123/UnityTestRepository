# 739 신고 작업 분리

기준: !210 병합 전 develop `33745590`. 브랜치: `feature/client/report-only`.

!210에 포함됐던 다른 담당자의 `feature/client/settings-ui` 파일과 커밋 이력을 제외하고, 739 신고 변경만 다시 구성했다. 되돌림 MR !211을 먼저 병합한 뒤 이 변경을 병합한다. !211의 추적 파일 트리는 `33745590`과 동일하다.

## 포함 범위

- Playground 신고 버튼/F8, 참가자·사유·선택 메모 입력과 기존 IReportGateway 제출.
- 자기 신고·잘못된 사유·200자 초과 메모·중복 제출 차단, 실패 안내, 화면 종료 시 요청 취소와 재진입 시 이전 응답 무시.
- 공개 계정 ID를 로그인 응답→연결 토큰→PlayerAvatar→RoomParticipant로 전달. 방 PlayerId를 계정 ID로 오인하거나 닉네임 검색으로 신고 대상을 추측하지 않는다.
- 신고 모달의 이동·카메라·채팅 입력 차단과 종료 시 커서 복구.
- 계정 ID 추가에 따른 네트워크 레이아웃 변경은 AppVersion `.account-roster-v2`로 이전 빌드와 매칭을 분리한다. 모든 참가자는 동일 빌드가 필요하다.

계정 ID는 인증 수단이 아니며 연결 토큰은 현재 클라이언트가 제시하는 값이다. Photon 인증과 서버 계정의 결합은 이 변경의 범위가 아니다. 신고는 관리자 검토 자료이고 자동 차단·제재·상대 알림을 발생시키지 않는다.

## 제외 범위

설정 화면·서비스·Settings 씬·그래픽/오디오/접근성/조작 설정, Settings 진입, 해당 브랜치의 기존 커밋. 740의 편집/적용/취소 보완은 기존 `9a5dc9a3`에 보존되지만 이 브랜치에는 가져오지 않는다. 다른 담당자의 설정 작업이 정식 통합된 후 별도 변경으로 연결한다.

## 검증

- 분리 상태에서 Game.Architecture.Tests 및 의존 프로젝트 컴파일 오류 0건.
- 독립 .NET 회귀 3건: 신고 계정 ID/입력/중복 제출, 닫기·재진입 후 늦은 응답, 연결 토큰 왕복/이전 형식/잘린 입력.
- 변경 파일에 설정 구현 경로가 없고, `d5ea7d73`이 이 브랜치의 조상이 아님을 확인한다.
- Unity 재임포트·Fusion weaving·동일 빌드 2인 신고 화면·실제 API 연동은 별도 검증이 필요하다. 독립 .NET 테스트를 실환경 검증으로 계산하지 않는다.
