# 신고·설정 공통 흐름 통합

기준 develop: `33745590`. 작업 브랜치: `feature/client/report-settings`.
기존 `origin/feature/client/settings-ui` (`d5ea7d73`)의 설정 화면·상태·저장소·적용기를 재사용해 통합했다. 기존 브랜치의 약 7,700줄을 포함하므로 신규 작성량과 구분한다.

## 739: 인게임 신고

- Playground의 신고 버튼 또는 F8 → 참가자 → 사유 → 선택 메모(200자) → 제출.
- 기존 IReportGateway를 호출한다. 자기 신고·잘못된 사유·긴 메모를 차단하고 전송 중 재클릭을 합친다. 성공 시 해당 폼의 추가 제출을 막고 실패 시 재시도할 수 있다.
- 닫기/Esc/F8/씬 종료 시 입력을 비우고 요청을 취소한다. 이전 폼의 늦은 응답은 재진입한 화면에 반영하지 않는다. 신고 모달 동안 이동·상호작용·카메라·채팅 입력을 차단한다.
- 방 PlayerId는 계정 ID가 아니므로 직접 API에 보내지 않는다. 로그인 응답의 공개 계정 ID를 연결 토큰과 PlayerAvatar를 통해 전달하고 RoomParticipant.AccountId로 선택한 참가자에 연결한다. 닉네임 검색으로 계정을 추측하지 않는다. 계정 연결이 없는 참가자는 신고 목록에서 제외한다.
- 계정 ID는 인증 수단이 아니다. 현재 Photon 연결 토큰은 클라이언트가 제시하는 값이며 인증된 서버 계정과의 암호학적 결합은 이번 작업에 포함하지 않는다. 신고는 기존 정책대로 관리자 검토 자료이며 자동 차단·제재·상대 알림을 발생시키지 않는다.

PlayerAvatar의 Networked 레이아웃이 변경된다. Photon 설정을 복사한 뒤 AppVersion에 `.account-roster-v2`를 붙여 기존 빌드와 매칭을 분리한다. 방 목록·방 생성/입장·복구에 같은 설정을 사용한다. 멀티플레이 검증 시 모든 참가자가 이 변경을 포함한 동일 빌드로 실행해야 한다. 연결 토큰은 v1 읽기를 유지하지만 이전 네트워크 빌드와의 접속 호환을 뜻하지 않는다.

## 740: 설정 공통 흐름

- 홈 설정 진입과 Settings 씬 등록, 현재 홈/방 찾기 조립 및 EventSystem과 통합.
- 기존 오디오·접근성·그래픽·키 바인딩 서비스에 편집 세션을 추가했다. 편집은 미리보기만 적용하고 저장하지 않는다. 적용 시 저장하며, 취소/이탈 시 마지막 적용값으로 복구한다.
- 미변경 시 적용/초기화 비활성. 초기화는 확인 후 기본값을 편집값으로 넣고, 미적용 이탈은 확인 후 취소한다. 적용 후 다시 편집해도 취소 기준은 마지막 적용값이다.
- 원래 설정 브랜치의 PlayerPrefs 저장소를 재사용한다. 메모리 저장소로 적용→새 서비스 생성 시 값 유지, 초기화 후 취소, 변경 확인 흐름을 검증했다. 실제 PlayerPrefs 재실행은 별도 확인 사항이다.
- 피드백 접수 계약과 번역 리소스가 없어 일반 탭은 한국어·피드백 준비 중을 표시한다. 전송 완료로 표시하지 않는다. 미연결 알림 토글도 준비 중 안내로 대체한다.

## 검증

- Game.Architecture.Tests.csproj 및 의존 프로젝트 컴파일 오류 0건. 새 asmdef 참조: Client의 UniTask 및 URP, 테스트의 InputSystem. Bootstrap의 Photon.Realtime 참조 유지.
- 컴파일된 테스트를 독립 .NET 실행기로 실행: 설정 상태/서비스/Presenter·홈·AppFlow·신고·연결 토큰 **95건 통과**. 비동기 Task는 완료까지 대기했다.
- Unity native 적용기 테스트와 Unity LogAssert scope가 필요한 홈 테스트 1건은 독립 실행에서 제외했다. 이 결과는 Unity Test Runner 실행 결과가 아니다.
- 신고 API 대상 ID·중복 제출·취소된 요청의 늦은 성공, 설정 적용/초기화 확인/취소/저장 스냅샷 회귀 포함.
- 충돌 표식 0건 및 코드·asmdef·문서의 Git 공백 검사. Unity 생성 메타의 빈 값 뒤 공백은 기존 형식을 유지한다. Settings 씬은 빌드 목록 끝에 추가해 기존 경기/결과 씬 인덱스를 유지한다.

## 남은 실환경 검증과 다음 묶음

- 피드백 접수 대상·지원 언어 확정과 실제 전송/번역 연결.
- 741~745: 최종 그래픽 옵션, 보이스/장치, 1·3인칭 감도, HUD 공개 범위, 알림 발생 경로는 기존 기반 코드의 통합만으로 완료 처리하지 않는다. 각 Task에서 실제 효과와 최종 명세 차이를 검증한다.
- 579 API 부하 테스트는 사용자 요청으로 후속 보류 유지.

Jira 상태는 사용자 요청에 따른 MR 생성 기준으로 반영하며, 남은 실환경 검증이 통과했다는 의미로 사용하지 않는다.
